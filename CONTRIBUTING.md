# Правила участия

Спасибо за интерес к devops-lab-arlanova! В проект можно добавлять учебные примеры, исправления и документацию по DevOps.

## Предложение изменений

1. Проверьте существующие Issues и Pull Request, чтобы не дублировать работу.
2. Для крупного изменения создайте Issue с описанием проблемы и предлагаемого решения.
3. Если у вас нет права записи, создайте fork репозитория.
4. Обновите локальную ветку `main` и создайте отдельную ветку, например `docs/linux-notes` или `feature/docker-example`.
5. Внесите изменения, ограничив один Pull Request одной понятной задачей.

## Требования к материалам

- Пишите понятно и уважительно; объясняйте назначение команд и примеров.
- Для лабораторных работ указывайте необходимые инструменты, шаги запуска и ожидаемый результат.
- Проверяйте команды и ссылки перед отправкой изменений.
- Для изменений кода запускайте доступные проверки и тесты; опишите результаты в Pull Request.
- Не добавляйте пароли, токены, приватные ключи и файлы с секретами. Используйте примеры с безопасными значениями.
- Не коммитьте временные файлы операционной системы и редактора.

## Коммиты и Pull Request

1. Создавайте небольшие коммиты с понятным описанием изменений.
2. Отправьте рабочую ветку в GitHub и откройте Pull Request в `main`.
3. Укажите в описании, что изменилось, зачем это нужно и как вы проверили результат. Добавьте ссылку на Issue, если он есть.
4. Ответьте на замечания ревью и при необходимости внесите исправления.
5. После проверки и слияния удалите рабочую ветку и обновите локальную `main`.

## Общение

Задавайте вопросы через Issues проекта. Обсуждайте решения конструктивно и с уважением к другим участникам.
